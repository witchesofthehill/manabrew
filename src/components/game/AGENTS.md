# Game UI — board, modals, panels, zones

The largest UI subtree. Read first: `src/AGENTS.md`, `docs/STYLE_GUIDELINES.md`, `docs/agents/UI_THEME_RULES.md`.

## Layout

| Folder / file                             | Role                                                                                                                                                                                                        |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GameBoard.tsx`, `Game.tsx` (in `views/`) | Top-level board composition.                                                                                                                                                                                |

## Board canvas — single unified Pixi scene

The whole table renders on **one** Pixi canvas, not one canvas per player. `BoardCanvas` (`@/pixi/BoardCanvas`) drives a single `BoardScene` (`@/pixi/board/BoardScene`) that hosts one `BoardRegion` per player, positioned by `computeBoardLayout` (`@/pixi/board/boardLayout`). Because every player's battlefield shares one coordinate space, cards can animate across the center line (MTGA-style combat staging) without crossing a canvas boundary.

- **Regions** (`BoardRegion`) own per-player grid layout, attachment stacking, rings, combat staging, and animation. The local region gets full interaction (drag/marquee/overlay); opponent regions are tap-to-target + hover only. Each reaches orchestrator services through a `RegionHost`.
- **Local controllers** live on the scene: `HandController`, `SelectionController`, `BattlefieldOverlay`, plus the `DragHandler` gesture. They talk to the scene through the `HandHost` / `SelectionHost` / `OverlayHost` seams in `@/pixi/board/types`.
- **Arrows + the spell stack** are not drawn inside `BoardScene`. A single transparent overlay canvas, `BoardOverlayCanvas` (`@/pixi/BoardOverlayCanvas`), sits _above_ the React panels (own Pixi app) and hosts both the `ArrowLayer` (pulls `BoardScene.getArrowDefs()` each tick) and the `StackLayer` (`@/pixi/stack/`). The canvas is `pointer-events: none` except while the cursor is over actual stack content — fanned cards, the expand button, or the flash card, via `StackLayer.hitTest`, **not** the fan's bounding rect (a window `pointermove` toggles it), so clicks elsewhere pass through; the fan's rect has big empty corners, and capturing them made the battlefield cards beneath silently hover-dead. The stack layer registers itself with `BoardScene.setStackAnchorProvider` so stack-origin arrows, the casting arrow, and fly-from-stack seeds all resolve from live Pixi sprites — there are no stack DOM nodes to query. The stack is a pure overlay: it never reflows the board beneath it (no keep-out rect), and its right inset is fixed (the bottom-anchored action panel never shares horizontal space with it). Stack spec is built in `Game.tsx` (`stackSpec`) and threaded through `GameBoard`. The pile has a user **collapsed** state (`useStackUIStore.collapsed`): a left-side button collapses it (shown when expanded), and a pulsing right-edge button expands it (shown when collapsed). Collapsing slides the fan right with a fast decelerating ease until only the top card's border peeks at the edge (under the expand button) — it never fully vanishes; a new card landing while collapsed auto-peeks the fan out for ~1.2s; while collapsed, top-card arrows anchor to the expand button.
- **Layout** keeps the local player along the bottom. The default **focused** layout gives opponents fixed, overlapping play rectangles across the top; moving delimiter masks reveal one field without re-gridding its cards. Optional **overview** assigns opponents full-width horizontal bands and fits each grid to its actual band height. Compact screens retain focused layout. `computeBoardLayout` owns these rectangles; `BoardCanvas` uses `scaleForRowsWithCombatRow` to fit cards without overflowing shallow bands.
- **Delimiters live in `BoardScene`.** In focused layout, `delimCurrent`/`delimTarget` partition the canvas into non-overlapping clip bands. Combat participants take precedence over manual focus, then hover, then active turn. Targeting, combat selection, hand drag, and inspection lock hover-driven refocusing. Overview bypasses delimiter easing and hides grips. Reduced motion snaps delimiter changes.
- **Touch input.** All gestures are pointer-event driven. `LongPressGesture` (`@/pixi/LongPressGesture.ts`) implements the app-wide **long-press = preview** convention on Pixi surfaces (battlefield sprites via `BoardScene`, zone tiles via `BoardZoneTiles`, stack cards via `StackCardSprite`); the release-tap is swallowed (`consumeTap`) so a hold never triggers the tap action. Every hand card enters `useHandDrag` (document-level `pointermove`/`pointerup`/`pointercancel`, filtered by `pointerId`): release over the hand lets `HandController` commit its Pixi insertion slot, release over the battlefield casts only when the card has a direct cast action, and touch hold tears the drag down for the sticky preview. `useHandOrder` owns the client-only stable ID order; the cog-opened `GameSettingsModal` changes the persisted Manual/Color/Mana value mode without touching engine snapshots. DOM chrome (ZoneViewer, SpellStackModal, ActionLog, CardImageThumbnail) uses `useLongPressPreview`.
- **Hover detection** is owned by `BoardScene`. Focused layout checks the cursor against delimiter bands; overview checks both coordinates against the opponent's rectangle. Region highlights use the player's seat color and report `onHoverOpponent`.
- **Pixi player HUD + on-grid zones**: the player panel is **all Pixi, always on** — there are no React player panels (the old `PlayerPanel`/`PlayerAvatar`/`BadgeOrbit`/`ZoneActionColumn` chain and the `pixiPlayerBar` pref were removed). It lives in `@/pixi/hud/`:
  - **`PlayerHudLayer`** owns one **`PlayerHudCapsule`** player plate per seat and a shared tooltip. Every non-collapsed plate uses the local plate's fixed mode-specific height, content alignment, and surface opacity; prompt/action-cluster resizing must not move or resize player plates, while collapsed opponent columns shrink only to fit their seat band. The local plate uses the bottom-right action cluster's 12px viewport-edge inset and docks through the battlefield bottom; opponent plates reuse its measured playmat-left overhang and dock through the battlefield top. The action cluster prefers 104px of height but is capped by the hand reserve, preserving the board's standard gap before skeleton rows. Plates use the same card surface, border, and 8px corner radius as that cluster. Identity/life, a highlighted fixed-slot mana tray, and a separate player-state tray have distinct regions. Shallow plates put Settings and Details in a utility dock below the portrait. W/U/B/R/G/C slots retain their positions and remain visible from zero; available mana uses full opacity while empty slots are muted. Narrow plates use a two-column mana grid. State badges use bounded grids with urgency priority and stable ordering within each priority; an empty state tray reads `No active effects` instead of presenting an unexplained blank region. `Details` / `+N states` opens the full live `PlayerSheetModal`, including each commander damage source. Turn accents, active-turn labels, and priority markers are independent and may appear together.
- **`BoardZoneTiles`** renders library, graveyard, exile, and command on reserved grid cells. Library, graveyard, and exile default to successive rows in the first available column; each region persists its selected fallback cells across relayouts, and explicit local drags update those same slots. Library uses a layered card-back stack; nonempty public zones show their top card and count. Empty graveyard and exile zones retain dotted card-slot outlines around their subdued glyphs and labels; all empty zones keep bounded hit areas. An opponent tile in the synthetic attack-row slot uses the stable full-field playmat inset so its complete card footprint remains inside the playmat border as delimiter bands resize. Opponent tiles remain static. `BoardCanvas.zoneTiles` feeds `BoardScene.setZoneTiles`; `BoardRegion` owns local drag/slot state and resolves fallback cells from `GridLayout`.
- **Keep-outs** use each plate's analytic rendered footprint in every layout, the local action-button cluster, and the visible hand strip. `refreshCapsuleBlockers` re-grids only when a plate footprint changes; regions do not add a second estimated HUD rectangle. `HandController.getBlockerRect` is root-local and independent of current hover/drag. Grid reserve and hand blockers use the same desktop/compact trim; the action cluster receives the full visible height. Grid debugging draws legal card slots and blocker rectangles separately; it does not render blocked cells as card-shaped placement options.
- **Mobile-minimal mode** (`useIsMobileGame` = short screen AND coarse pointer; desktop is byte-identical when it's false):
  - **Phase strip** (`@/pixi/PhaseStripLayer`): compact renders the current phase as a tappable pill. Expanding it reveals the full stop controls without reflowing the board; outside tap or idle collapses it. Desktop keeps the full phase sequence and combat substeps. Controls sit between the separated playmats without a full-width divider line or backing band. Turn and priority remain explicit in the strip status and player plates. The strip stays readable during combat.
  - **Action cluster** (`panels/MainActionOverlay`): the header/title/chevron disappear and prompt leaves under `components/prompts/` render icon-pill variants (each leaf gates itself with `useIsMobileGame`; `PromptActionButton` stacks a micro-label under the icon there, since its hover tooltip is unreachable on touch). The cluster anchors **vertically centered on the phase strip** (`dividerY` from `BoardCanvasLayout`, passed as a prop from `Game.tsx`), right-aligned. The hidden hints/title move to a **long-press context popover** (`useLongPressPreview` on the cluster, content from `panels/promptContextHints.ts`, portaled to `document.body`). Prompt modals shrink via a minimal branch in `prompts/internal/PromptPresentation.tsx`.
  - **Hand fan** rests partly below the canvas edge, sinking further in compact mode (`HAND_BOTTOM_SINK_FRAC_COMPACT` versus `HAND_BOTTOM_SINK_FRAC`). Hover lifts and enlarges the card while pushing neighboring cards aside. Opening hands use the same fan and mulligan controls as normal play, without a separate raised presentation or veil. Whole-table pinch zoom retains its existing behavior.
  - **Player plates** retain readable type instead of scaling the whole HUD down. Narrow opponent bands use a vertical layout; shallow horizontal plates place the player name above the portrait and life immediately to its right whenever their height can contain the portrait, while extremely short plates omit it. Opponent plates reuse the local plate's measured playmat-left overhang and dock through the outer top edge, including within focused and collapsed bands. The local plate prefers the battlefield's bottom-left chrome position, narrows toward the hand when enough usable width remains, and moves above the hand only when necessary to prevent overlap.
  - **Zones move onto the player plate** in compact mode, except command stays on-grid. Expanded plates show zone buttons beside hand count; full player inspection retains their live `onTap` actions when the plate is narrow or shallow. HUD/zone anchors serve movement and targeting. Command tiles show the snapshot's optional `commanderTax`; never derive it from mana cost or local cast history.
  - **Row fitting** uses the exact shared solver, including playmat inset, trimmed hand reserve, and combat band. Compact targets three rows; overview caps opponent grids at one row plus their combat band. The hand reserve derives from its visible fraction and `HAND_RESERVE_TRIM` / `HAND_RESERVE_TRIM_COMPACT`.
  - **Battlefield long-press** opens the **sticky** card preview (with the existing flip/rotate buttons and outside-tap dismiss): `BoardScene.fireLongPressPreview` → `GameCanvasCallbacks.onLongPressCard` → `Game.tsx` `preview.showSticky`. `CardPreview` clamps its size to the viewport height in compact mode.
  - **Collapsed opponent identity tap = focus** (compact + multiplayer only): `BoardScene` intercepts avatar/header activation and fires `onFocusOpponentField` → `GameBoard.setManualFocusId`. Badge and overflow inspection use a separate callback so they still open `PlayerSheetModal` while the field is collapsed. Expanded headers open the sheet directly.
  - **ManaAbilityTapButton** long-press shows a transient description popover (the hover `title` equivalent).
  - **Card-relative chrome** scales with the sprite. Compact sprites/tiles get a touch hit-pad from the free cell pitch, and rings remain at least two screen pixels. Battlefield overlays select contextual targets only; ordinary taps inspect.
  - **Player-panel lab**: `GameDevPanel`'s Player workspace can force every identity, turn, targeting, combat, connection, badge, counter, life, hand, incoming-damage, and W/U/B/R/G/C mana-pool state across every seat. `BoardPlayground` also has a four-player `player-panels` scenario with simultaneous states, partner commander damage, and independently editable floating mana. Turn/priority changes leave those fixtures intact. Its overflow opens the same live player detail sheet as the game.
  - **Native tap feel** is global CSS, not mobile-gated: `index.css` sets `-webkit-tap-highlight-color: transparent` on body, `touch-action: manipulation` on tappable elements, and the `.game-touch-surface` class (on the `Game.tsx` root and the `Modal` backdrop — modals portal to `document.body`, outside the game root) suppresses text selection, iOS image callout, and image drag ghosts; inputs keep text selection.

The legacy per-player canvases (`PixiGameCanvas` / `PixiGameScene` / `PixiArrowsCanvas` / `PixiPhaseStripCanvas` / `OpponentHalf`) have been removed — do not reintroduce them.

## Modal pattern

All game modals use the `Modal` compound:

```tsx
<Modal onClose={onCancel} maxWidth="max-w-md">
  <Modal.Header>{/* title + optional source-card thumbnail */}</Modal.Header>
  <Modal.Instructions>Instruction text</Modal.Instructions>
  <Modal.Body>{/* content */}</Modal.Body>
  <Modal.Footer>{/* buttons */}</Modal.Footer>
</Modal>
```

Use `MODAL_CARD_THUMBNAIL` / `MODAL_CARD_IMAGE` / `MODAL_FOOTER_BETWEEN` constants. Use `useModalKeyboard` for Enter/Escape handling. Use `CardImageThumbnail` for header art.

Backdrop dismissal is **click-based but armed after `GHOST_CLICK_ARM_MS`** (`lib/responsive.ts`): a touch tap on a Pixi surface that opens a modal fires its synthetic click after the modal mounts (instant-close if unarmed), while pointerdown-dismissal unmounts the backdrop before that click dispatches and retargets it onto game controls underneath. Any overlay that opens from a Pixi tap and dismisses on outside interaction needs the same arming treatment (`CardPreview` uses the equivalent delayed window listener).

For a modal that renders a list/grid of cards the user searches through (zone viewers, tutors, choose-from-zone), gate a name filter with `useCardNameFilter(cards)` (shows only past ~10 cards) and render `<ModalCardFilter>` between the header/instructions and `Modal.Body`, mapping its `filtered` instead of the raw `cards`. Pass `autoFocus` only when the modal has no Space/Enter-to-confirm (otherwise the focused input swallows the shortcut).

## Mana text

Any text that may contain `{W}`, `{2}{R}`, etc. renders through `DynamicTextRender` (`TextWithMana` no longer exists):

```tsx
<DynamicTextRender className="align-middle" text={description} />
```

Don't roll your own symbol parsing.

## Card rendering — keep the three renderers in sync

A card's look is produced by **three independent renderers**. They share no draw code, so any visual change must be applied to all three (or consciously skipped with a note):

| Renderer                              | Tech | Where it shows                                                                                      |
| ------------------------------------- | ---- | --------------------------------------------------------------------------------------------------- |
| `@/pixi/CardSprite`                   | PIXI | In-game battlefield + hand (the real game)                                                          |
| `components/game/BattlefieldCardFace` | DOM  | Custom battlefield styles (art-forward / mini-frame) — settings preview, dev gallery (`/card-mock`) |
| `components/game/CardPreview`         | DOM  | Hover preview popup (and deck-editor hover)                                                         |

**Rule:** when you add, restyle, or remove a card visual — counters, damage wash, summoning-sickness, P/T coloring, frame tint/bars, keyword chips, mana pips, foil, badges, etc. — change **every** renderer that should show it, in the same commit. A change that lands in only one drifts the others (this has bitten us repeatedly: FPS-style regressions, counter display, damage-wash corners, summoning sickness).

- **Shared, theme-driven color math lives in `@/themes/gameTheme.ts`** (`frameTint`, `readableTextColor`, `withAlpha`, `darken`, `relativeLuminance`). Use these in both DOM and Pixi instead of re-deriving — that's what actually keeps the look identical across renderers. No hex literals (see Theme below).
- **Geometry must match too.** A full-card overlay must trace the card's rounded corner: in the DOM the card border is drawn as an `inset-0 rounded-[inherit]` overlay (not a CSS `border`) so washes can fill to the outer radius; in Pixi the equivalent is a `roundRect(..., CARD_RADIUS)`.
- **The realistic P/T badge is one shared component — `PtBadge`.** The bottom-right P/T overlay on the DOM renderers (`Card`, `CardPreview`) is `PtBadge`, sized in container units (`cqw`) + `em` so it is the same fraction of the card on every surface (stack, modals, zones, hover preview) regardless of pixel size. Its card root must set `@container`. Don't re-hard-code a px-sized P/T span — drift here is exactly what made the stack/preview/hand badges different sizes. Hand cards don't draw a Pixi P/T overlay because the printed image already carries it. Battlefield cards draw `CardSprite.updatePT` in every style, and the card DTO must retain `types`, effective `power`/`toughness`, and printed `basePower`/`baseToughness`; all renderers compare effective against base to choose buffed, debuffed, or neutral color. The staged Scryfall card follows this same contract. The DOM art/mini-frame face (`BattlefieldCardFace`) lays P/T into its frame bar.
- **Attacking + summoning-sickness now match the DOM in Pixi too:** both draw an inset **edge glow** (`CardSprite.updateEdgeGlow`) — red for attacking, frosty + pulsing for summoning-sick (pulse driven per-frame by `BoardRegion.animate` → `tickEffects`); summoning-sick also keeps the grey desaturate/dim filter. Pixi's `setRing` is now reserved for **interaction/combat** states only (lethal, pending, tappable/untappable land, selectable/targeting).
- **Known intentional divergences — do not "fix" without being asked:** some effects are **Pixi-only** (doomed wash, foil ring, ring-bearer, status badges `MORPH`/`EXERTED`/…, damage-order badge, stack count). The DOM face also currently lacks the _debuffed_ P/T color that Pixi has.

## Card preview (hover / sticky)

One preview system serves the whole app (game, deck editor, limited, modals), in three layers:

| Layer    | File                                                                                                                      | Role                                                                                                                                                                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Machine  | `lib/cardPreview.ts` (`CardPreviewMachine`)                                                                               | Sole owner of preview state + every timer. **All timing knobs are `PREVIEW_TIMING` in that file** (warm/cold show delay, leave grace, enter/exit animation, battlefield hover-out hold); the cold show delay is the user's "Card Preview Delay" preference. |
| Hook     | `hooks/useCardPreview.ts`                                                                                                 | Thin React binding (`useSyncExternalStore`, stable callbacks). Applies the modifier-mode / hover-delay preferences as input filtering.                                                                                                                      |
| Renderer | `components/game/HoverCardPreview` → `CardPreview` (+ `CardPreviewOverlay`, `CardPreviewActions`, `cardPreviewLayout.ts`) | Dumb presentation. Placement math is the pure `computePreviewLayout`. `CardPreviewRail` is the reusable pinned presentation shell; it owns its portal slot, collapse and resize behavior, and accepts optional consumer-specific details.                   |

Rules — these encode fixed bugs, keep them:

- **Never unmount the preview on transient state.** Engine prompt churn (a prompt answered and replaced within a frame) must not blink the DOM: pass `suppressed` to `HoverCardPreview` (opacity fade; hover state survives) instead of adding conditions to the mount gate. Unmount-gating on `promptType` is exactly what caused the show/hide/show flash.
- **Explicit UI takeovers dismiss.** Zone viewer, spell stack modal, ability picker, hand drag: dismiss via the hook's `dismissDeps` argument or `dismiss()` (synchronous — never `setTimeout(dismiss)`).
- **Instant card-switching is only allowed while `open`.** A dismissed preview re-enters through the hover delay; the machine enforces this so a pointermove racing a dismiss can't re-show it for a frame.
- **`phase === "closing"`** keeps the card rendered for the exit animation (`PREVIEW_TIMING.exitMs`); `hoveredCard` is non-null during it.
- **The machine is warm for `warmWindowMs` after a preview was visible**: hovers during that window show at `warmShowDelayMs` instead of the preference delay, so browsing a board feels fluid without making the first popup twitchy.
- **Enter/exit is a hero zoom from the hovered card's rect**: `CardPreview` feeds `--preview-shift-x/y` + `--preview-scale-from` (computed from `anchorRect` vs the final position) into the `preview-in`/`preview-out` keyframes in `index.css`. Keep the animation anchored — an in-place zoom reads as a blink.
- **The preview is pointer-transparent until the enter lands** (`entered`, timer-armed — not `animationend`, which never fires under `prefers-reduced-motion`). The hero zoom travels across the hovered sprite; an interactive preview crossing the cursor steals pointer events from the canvas and kills the sprite's hover state.
- **Card face chrome matches Pixi**: corner radius is proportional (`CARD_RADIUS / CARD_W` of card size — shared constants in `game.constants.ts`) and the border is a `cardFrameTintHex` (color-identity) inset ring from `@/themes/gameTheme`. Don't reintroduce fixed `rounded-*` on the preview card.
- **Images are monotonic** (`PreviewImageStack` in `CardPreview`): pixels already shown are never removed until the replacement loads. Swapping an `<img>` src blanks it instantly — a naive URL swap (Scryfall faces resolving, low→high res, card switch) is the image flash.
- **Battlefield hover-out is `BoardScene`'s** (`scheduleHoverClear`, also fired on sprite `destroyed` — a removed sprite emits no `pointerleave`). Hover is also **re-asserted on every `pointermove` over any sprite** (force `setBattlefieldCardHovered` — not just the remembered card): a spurious `hoverEnd` (the preview firing enter/leave as it jumps positions during an instant switch) must not close a preview while the cursor sits on the card, and a `pointerenter` swallowed whole by the hand-hover gate (`hasActiveHover`, e.g. the fan grazed mid-sweep) leaves the scene with a stale hover belief that only raw pointer truth can repair — gating the re-assert on `hoveredCardId` is exactly what made a preview die permanently on the card you stopped on. The machine keeps the re-assert free — `hoverStart` early-returns when the same card **object** is already open, and a changed DTO object refreshes the open preview.
- **Inspection is separate from battlefield action.** Click-only preview is the default; hover and modifier modes remain preferences. Pixi hover callbacks without DOM events use captured keyboard/pointer modifier state. Ordinary battlefield and zone clicks inspect; explicit legal actions and permitted battlefield drops submit responses. Hand clicks execute a single legal action or offer multiple actions through sticky inspection; unanchored multi-action clicks use the play-mode picker. Manual-mode hand clicks inspect. Targeting and combat prompts retain direct selection. Attachment piles open a viewer containing the host and every descendant, with legal target IDs refreshed across re-prompts.
- **Movement follows snapshots.** `BoardScene.setZoneDestinations` runs before region and hand updates so departures can use their live positions. Known stack departures and battlefield exits travel toward authoritative zone anchors. Hidden identities remain hidden; disappearance alone is not a resolution signal. Seed positions and scales are canvas-global, converted through the root transform at region boundaries.

## Prompt routing

The engine sends a `Prompt` (from `@/protocol`) → `PromptModalHost` (in `prompts/promptComponents.tsx`) looks up `prompt.input.type` in the `PROMPT_MODALS` registry and renders that entry inside `PromptModalController`. Each registry entry receives `{ prompt, respond, ctx }` — it reads the typed `prompt.input`, renders a leaf modal from `modals/`, and answers by calling `respond(<PromptOutput>)` directly (no per-prompt store callback). `ctx` carries the misc UI extras the engine prompt doesn't (`sourceDeckCard`); non-prompt overlays (zone viewer, spell stack, ability picker) live in `GameOverlays`, not the registry.

To support a new prompt: add `src/protocol/prompts/<name>.ts` (`Type`/`Input`/`Output`), add it to the unions in `protocol/prompts/index.ts`, add a `PROMPT_MODALS` entry, and build the modal under `modals/`. The Rust counterpart lives in `manabrew-rs/crates/manabrew-agent-interface/src/prompt.rs`.

## Theme

This subtree is the most color-heavy in the app. **No hex / rgba / palette tailwind.** Add a semantic key to `GameThemeColors` (in `src/themes/gameTheme.ts`), wire it in `buildGameColors()` (in `src/themes/buildGameColors.ts`), regenerate the Tailwind `@theme` block with `node scripts/generate-theme-css.mjs --write`, then use the generated token utility (`bg-pointer-hostile`, `text-counter-p1p1`, `ring-card-ring`, `bg-pt-buffed`, …). See `docs/agents/UI_THEME_RULES.md`.
