Sent when the player has priority: cast a spell, play a land, activate an
ability, or pass. The reference client shows no dialog for it. It highlights
the actions on the board.

## Response

```ts
type ChooseActionOutput =
  | { type: "pass"; until?: PassUntil; exhaustStack: boolean }
  | { type: "restoreSnapshot"; checkpointId: number }
  | { type: "act"; actionId: string };

type PassUntil = { playerId: string; phase: StepKind };
```

`act` performs the action with that `id`. Tapping a mana source and untapping
one (`undoMana`) are actions like any other. `actionId` must be an `id` from
this prompt's `actions`, or the engine [rejects it](/protocol/#errors).

`pass` passes priority. With `until`, the engine keeps passing for this player
until `playerId` reaches `phase` (a [`StepKind`](/protocol/game-view/)). With
`exhaustStack: true`, it keeps passing until the stack is empty. Either way
it stops early and sends a new prompt as soon as anything new goes on the
stack, so the player can respond.

Conceding is not a response. It is the `directive` message
(see [Answering a prompt](/protocol/#answering-a-prompt)), legal at any time.

## Example

```json
{
  "promptId": 7,
  "decidingPlayerId": "player-0",
  "input": {
    "type": "chooseAction",
    "actions": [
      {
        "id": "act-0",
        "type": "cast",
        "cardId": "hand-2",
        "mode": "cast",
        "modeLabel": "Cast Lightning Bolt"
      },
      {
        "id": "tap:perm-5:0",
        "type": "activateAbility",
        "cardId": "perm-5",
        "abilityIndex": 0,
        "description": "{T}: Add {G}.",
        "isManaAbility": true,
        "producedMana": [{ "color": "G", "amount": 1 }]
      }
    ]
  }
}
```

```json
{
  "kind": "response",
  "promptId": 7,
  "action": {
    "type": "chooseAction",
    "output": {
      "type": "pass",
      "exhaustStack": false
    }
  }
}
```
