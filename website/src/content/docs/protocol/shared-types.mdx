The prompt protocol is built from a small set of reusable structures. Instead of
redefining them on every prompt page, they're collected here - each prompt's
arguments link back to the entries it uses.

## PromptPresentation

The title/description header most modal prompts open with.

<ProtocolType type="PromptPresentation" />

## TargetRef

A typed reference to a player, card, or spell. The `kind` field says which id
space `id` belongs to; `intent` and `oracle` optionally annotate the target.

<ProtocolType type="TargetRef" />

## TargetKind

Which id space a [`TargetRef`](#targetref) points into - a player, a card, or a
spell on the stack.

<ProtocolType type="TargetKind" />

## ScryDestination

The zones a scry-style prompt can sort cards into.

<ProtocolType type="ScryDestination" />

## DiceRollEntry

One player's dice result.

<ProtocolType type="DiceRollEntry" />

## AvailableAction

One legal action offered by [chooseAction](/protocol/choose-action/): cast a
spell, activate an ability, or undo a mana activation.

<ProtocolType type="AvailableAction" />

## ActivatableAbilityInfo

A mana ability the player can activate while paying a cost
([payManaCost](/protocol/pay-mana-cost/)).

<ProtocolType type="ActivatableAbilityInfo" />

## AttackerOptionDto

A creature that can attack, with the set of targets it may attack
([chooseAttackers](/protocol/choose-attackers/)).

<ProtocolType type="AttackerOptionDto" />

## AttackTargetDto

Something an attacker can be declared against - a player, planeswalker, or battle.

<ProtocolType type="AttackTargetDto" />

## AttackTargetKind

Which kind of thing an [AttackTargetDto](#attacktargetdto) is.

<ProtocolType type="AttackTargetKind" />

## BlockableAttackerDto

An incoming attacker and how it may be blocked
([chooseBlockers](/protocol/choose-blockers/)).

<ProtocolType type="BlockableAttackerDto" />

## TokenScript

The Forge token definition used to distinguish tokens with the same name but
different rules, such as two 2/2 white Knight tokens with different abilities.
It is an opaque string on the wire; values follow Forge's token-script names,
typically `colors_power_toughness_type_abilities`, for example
`w_2_2_knight_vigilance`. See Forge's
[`tokenscripts`](https://github.com/Card-Forge/forge/tree/master/forge-gui/res/tokenscripts)
directory for the canonical definitions.

<ProtocolType type="TokenScript" />
