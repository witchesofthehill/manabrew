A [`StateUpdate`](/protocol/#message-families) has one field, `gameView`, a
full `GameViewDto` snapshot. It is the only carrier of game state. The client
drops its previous view and redraws from each one.

## GameViewDto

Turn structure, players, battlefield, stack and game-end state.

<ProtocolType type="GameViewDto" />

## PlayerDto

One player's scalars: life, counters, mana pool, statuses. Cards are in the
top-level `zones`, not on the player.

<ProtocolType type="PlayerDto" />

## ZoneDto and CardView

One `ZoneDto` per `(zone, owner)` pair. Its `cards` are `CardView`s, top
first where the order is public. `count` is the zone's size.

<ProtocolType type="ZoneDto" />

<ProtocolType type="CardView" />

An engine that builds a view per recipient applies visibility per card:

- Hands: visible entries for the owner, or under a reveal effect. Other seats
  get `count` only.
- Library: `count` only, plus the top card when the recipient may look at it
  ("play with the top card of your library revealed").
- Face-down exile (foretell and the like): a `hidden` entry per card. The
  client draws a face-down card and learns nothing.
- Face-down permanents (morphs): the permanent is public. A recipient who may
  not see the face gets a redacted `CardDto`, blank `identity`, no text or
  costs. Counters, tapped state and power/toughness stay. The client draws a
  card with an empty `identity.name` as a card back.

## StepKind

Where the turn stands, `GameViewDto.step`. Also used by
[`chooseAction`](/protocol/choose-action/)'s pass-until response.

<ProtocolType type="StepKind" />

## CardDto

One card. Only `id` and `identity` are needed to answer a prompt. The rest is
for rendering.

<ProtocolType type="CardDto" />

## CardIdentity

Which card a `CardDto` or `StackObjectDto` is: name, printing
(`setCode`/`cardNumber`), and whether it is a token.

<ProtocolType type="CardIdentity" />

## CombatAssignmentDto

A declared block: which blocker is assigned to which attacker.

<ProtocolType type="CombatAssignmentDto" />

## StackObjectDto

A spell or ability on the stack. Its `targets` are
[`TargetRef`](/protocol/shared-types/#targetref)s, each with the
[`TargetingIntent`](#targetingintent) the engine inferred.

<ProtocolType type="StackObjectDto" />

## TargetingIntent

What an effect means to do to its target. The client uses it to highlight
likely targets. Carried by [`TargetRef`](/protocol/shared-types/#targetref)
and the targeting prompts.

<ProtocolType type="TargetingIntent" />

## State patches

An engine may send a `stateDelta` instead of a `state`. It carries a `patch`
against the last state the client applied, `base` (that state's fingerprint)
and `fingerprint` (the result's). An engine that sends patches also puts
`fingerprint` on every full `state`.

A client applies the patch only when `base` matches the fingerprint of the
state it holds.

Patches are optional. An engine may always send full states. A client should
accept patches.

### Patch encoding

A patch has the shape of the `state` it edits. Objects merge: each key in the
patch applies to the same key in the state, keys not in the patch are left
alone. Four reserved keys do the rest:

| Key  | Meaning                                                                |
| ---- | ---------------------------------------------------------------------- |
| `$v` | Literal replacement.  |
| `$d` | Removal.  |
| `$k` | Keyed array edits. An object of element key to patch.                  |
| `$o` | Keyed array order. The full list of element keys, in their new order.  |

Arrays whose elements all have a stable key are edited element by element
under `$k`. The key is the element's `id`; zone entries have none, so theirs is
`"<zone>/<ownerId>"`. `$k` on a missing key inserts at the end. `$o` lists
every key in the new order and is omitted when the order did not change. Any
other array is replaced whole.

Scalars and arrays appear as themselves, so `null` is a value, not a deletion.
An object that must replace instead of merge is wrapped in `$v`.

### Example

Player 1's Lightning Bolt (`card-7`) resolves against player 0. The stack
empties, the card goes on top of player 1's graveyard, player 0 is at 17 and
has priority:

```json
{
  "kind": "stateDelta",
  "base": "9f3c1a0e5b7d2461",
  "fingerprint": "4d0e8b2a7c91f356",
  "patch": {
    "gameView": {
      "priorityPlayerId": "player-0",
      "players": {
        "$k": { "player-0": { "life": 17 } }
      },
      "zones": {
        "$k": {
          "graveyard/player-1": {
            "count": 2,
            "cards": {
              "$k": { "card-7": { "$v": { "visibility": "visible", "id": "card-7", ... } } },
              "$o": ["card-7", "card-3"]
            }
          }
        }
      },
      "stack": { "$d": ["card-7"], "$o": [] }
    }
  }
}
```

`players` keeps its order, so it has `$k` and no `$o`. The graveyard gains a
new element, so its full `CardView` arrives under `$v` and `$o` puts it first.
The stack loses its only element, so `$o` is empty.
